# Поворот на 90° с автосохранением и наклон (tilt)

Дата: 2026-10-03. Статус: черновик на ревью.

## Зачем

Открыл фото, увидел, что оно лежит на боку, повернул одной кнопкой, закрыл окно, и поворот остался в файле. Как в «Фотографиях» Windows: без «Сохранить», без диалога. Кроме поворота в исходный файл не попадает ничего: рамка, W×H, формат, зум и наклон живут только в приложении.

Наклон с шагом 1° выравнивает горизонт перед обрезкой, как в редакторах на телефоне. Он действует только на сохраняемую обрезку и в исходник не пишется.

## Решения, принятые на брейншторме

| Вопрос | Решение |
|---|---|
| Как писать поворот JPEG | Тег EXIF Orientation. Сжатые данные изображения не меняются ни на байт. |
| Как писать поворот PNG | Попиксельный поворот без потерь в Rust: PNG не поддерживает EXIF-ориентацию в Chrome и Firefox. |
| Управление наклоном | Кнопка угла на верхней панели и линейка во всплывающем окне со стрелками ±1°. |
| Пустые углы при наклоне | Видны. Рамка не может заехать на фон. |
| Панель в режиме фокуса | Кнопки поворота прячутся вместе с панелью. На касание первый тап по верхней полосе только показывает панель. |

## Область работ

**Входит:**
- Поворот на 90° влево и вправо: показ на экране и автосохранение в файл.
- Наклон ±45° с шагом 1°: показ на экране и учёт при экспорте обрезки.
- Ctrl+O через нативный диалог `dialog.open` вместо `<input type=file>`: так у файла есть путь, поворот можно сохранить, и Prev/Next тоже начинают работать. Это закрывает пункт из бэклога.
- Тап по верхней полосе в режиме фокуса.
- Тесты, справка по клавишам, README, CLAUDE.md.

**Не входит:**
- Отражение по горизонтали и вертикали.
- Наклон точнее 1°.
- Сохранение наклона в исходный файл.
- Путь к файлу при перетаскивании. Для этого нужно `dragDropEnabled: true` и перенос обработки в Tauri. Файл, брошенный в окно, поворачивается только на экране, и подсказка говорит об этом.
- Отмена поворота кнопкой «Отменить». Поворот в обратную сторону и есть отмена.

**Выпуск:** отдельной версией 0.1.6, до 0.2.0.

## Интерфейс

### Верхняя панель

```
[⟲▢][⟳▢][∠ 0°] │ [📂][▢][⛶][?]
 правка картинки │  приложение
```

- **Иконки поворота:** стрелка вокруг квадрата, как rotate-ccw-square и rotate-cw-square в Lucide. Обычные ⟲ ⟳ читаются как «Отменить/Повторить».
- **Кнопки:** существующий компонент `.iconBtn`. Между двумя группами вертикальный разделитель, тот же, что `.div` в пилюле.
- **Кнопка угла** `#tiltBtn` оформлена как `#zoomBtn`: высота 24 px, рамка `--line`, моноширинные цифры. При угле ≠ 0° у неё класс `.on`: голубой цвет `--cyan` и фон `--cyanSoft`. Клик открывает линейку.
- **До открытия файла** новые кнопки скрыты, как `#cropToggleBtn`.
- **Ширина до 460 px:** скрыт счётчик `#navPos` (стрелки ‹ › остаются), `.iconBtn` сужается до 28 px.
- **Ширина до 560 px:** как сейчас, скрыты `#helpBtn` и `#zoomBtn`.
- **Сенсорный ввод** (`@media (pointer:coarse)`): высота панели (`--bar`) 44 px, кнопки 44×40, высота линейки не меньше 48 px.

Подсказки при наведении:

| Элемент | Текст |
|---|---|
| ⟲ | «Повернуть влево (L). Сохраняется в файл» |
| ⟳ | «Повернуть вправо (R). Сохраняется в файл» |
| ∠ | «Наклон (клавиши [ и ]). Только для сохраняемой обрезки» |

### Линейка `#tiltPop`

```
┌──────────────────────────────┐
│ [‹]       −3°        [›] [0°]│
│ ·|····|····▲····|····|····|· │
│ -15  -10  -5   0   +5  +10   │
└──────────────────────────────┘
```

- Основа: существующий `.pop` (фон `--pop`, рамка `--line`, радиус `--r-l`, анимация `popIn`). Окно ставится **под** верхней панелью и привязано к `#tiltBtn`. Нужен новый вариант позиционирования рядом с `placePop`, который сейчас умеет ставить окно только над пилюлей. Окно не выходит за края, это проверяет `layout.spec.mjs`.
- Шкала движется под неподвижной голубой меткой. Мелкие деления через 1° цвета `--muted`, подписи через 5° шрифтом `--mono`. Над меткой крупное текущее значение.
- **Перетаскивание** мышью или пальцем: угол меняется с шагом 1°, около 0° линейка слегка «примагничивается». **Колесо** над шкалой ±1°. **Двойной клик** сбрасывает в 0°.
- **Кнопки** `‹` и `›` дают ±1°, кнопка `0°` сбрасывает угол.
- **Доступность:** `role="slider"`, `aria-valuemin=-45`, `aria-valuemax=45`, `aria-valuenow`, `aria-valuetext` («минус 3 градуса»). С клавиатуры: ←/→ ±1°, Home даёт 0°.
- **Закрытие:** Esc или клик вне окна, как у остальных `.pop`. Пока окно открыто в режиме фокуса, верхняя панель остаётся видимой.

### Сетка при наклоне

- Частая сетка `#tiltGrid` выровнена по экрану, а не по картинке, чтобы горизонт было с чем сравнить. Линии `rgba(255,255,255,.4)`, как у `.thirds`.
- Видна только во время настройки (перетаскивание линейки, ±1° с кнопок или клавиш) и гаснет через 1 с.

### Режим фокуса и сенсорный ввод

- **Мышь:** как сейчас. В режиме фокуса панель прозрачна и проявляется, пока курсор над ней.
- **Касание:**
  - Полоса высотой `max(var(--bar), 56px)` сверху: первый тап (`pointerType === "touch"`), пока панель скрыта, только показывает её (класс `body.barPeek`). Событие перехватывается в фазе захвата, поэтому кнопка под пальцем не нажимается.
  - Тапы, пока панель видна, работают как обычно.
  - Панель прячется через 3 с без касаний или после тапа ниже полосы.

## Как это устроено на странице

### Состояние

- `quarterTurns` (0–3): четверти поворота относительно загруженной картинки.
- `tilt` (целое, −45…45): угол наклона.

Оба сбрасываются при загрузке любого файла (`loadFile`). Картинка заново не декодируется и не перерисовывается: `imgEl` остаётся исходным, а EXIF-ориентацию файла Chromium применяет сам.

### Геометрия: `frontend/geometry.js`

Новый файл, ES5, без зависимостей. Подключается в `index.html` через `<script src="geometry.js">`. Экспортирует `window.PccGeometry`, а в Node — `module.exports`, чтобы его можно было тестировать без браузера. Все функции чистые и работают в координатах stage (экранные px).

- `orientedSize(w, h, quarterTurns)`: `{w, h}` после поворота на 90°.
- `boundingSize(w, h, deg)`: габарит прямоугольника w×h, повёрнутого на `deg`.
- `isBoxInside(box, rect)`: все 4 угла рамки внутри наклонённого прямоугольника картинки. `rect = {cx, cy, w, h, deg}`.
- `clampBoxCenter(box, rect)`: ближайшее допустимое положение рамки с тем же размером.
  - Центр переводится в систему координат картинки и по каждой оси зажимается в `±(W/2 − (w·|cos|+h·|sin|)/2)` и `±(H/2 − (w·|sin|+h·|cos|)/2)`, затем переводится обратно.
  - Если рамка не помещается при любом положении центра, сначала вызывается `maxBoxSize`.
- `maxBoxSize(aspect, rect)`: наибольшая рамка с этим соотношением сторон, `h = min(W/(a·c+s), H/(a·s+c))`, где `c = |cos|`, `s = |sin|`.
- `maxWidthFromAnchor(anchor, growX, growY, aspect, rect, minW)`: наибольшая ширина при растягивании за угол. Бинарный поиск, 40 шагов, проверка через `isBoxInside`.

При `deg = 0` все функции дают ровно то же, что нынешние `clamp(…, 0, display.w − box.w)`. Поэтому существующие тесты рамки остаются в силе.

### Показ на экране

- `natural` становится ориентированным размером: `orientedSize(imgEl.naturalWidth, imgEl.naturalHeight, quarterTurns)`.
- Размер stage равен `boundingSize(natural.w, natural.h, tilt) × display.scale`. `computeBaseScale` вписывает в окно этот габарит.
- `<img>` позиционируется по центру stage с `transform: rotate(quarterTurns·90 + tilt deg)` относительно центра. Размер элемента — исходный `naturalWidth × naturalHeight × scale`.
- `#stage` получает прозрачный фон: пустые углы цвета `--surround`. Затемнение вокруг рамки (`box-shadow` у `#cropBox`) остаётся.

### Поведение рамки

| Действие | Что происходит |
|---|---|
| Перемещение (`startDrag` «move», `nudge`) | `clampBoxCenter` вместо зажатия по осям |
| Растягивание за угол | `maxWidthFromAnchor` вместо `maxW`/`maxH` |
| Новая рамка (`onTargetChanged`) | `fitBox` в видимой области, затем `maxBoxSize` и `clampBoxCenter` |
| Поворот на 90° | зум сбрасывается к «вписать», рамка ставится заново (`fitBox`), угол наклона сохраняется |
| Изменение наклона | центр и размер рамки сохраняются; если рамка не помещается, она уменьшается (`maxBoxSize`) и сдвигается (`clampBoxCenter`) |

Множитель зума при изменении наклона сохраняется, `baseScale` пересчитывается.

### Экспорт

Холст `targetW × targetH`, пересчёт пикселей один, из оригинала:

```js
ctx.scale(targetW / box.w, targetH / box.h);
ctx.translate(-box.x, -box.y);
ctx.translate(stageW / 2, stageH / 2);
ctx.rotate((quarterTurns * 90 + tilt) * Math.PI / 180);
ctx.scale(display.scale, display.scale);
ctx.drawImage(imgEl, -imgEl.naturalWidth / 2, -imgEl.naturalHeight / 2);
```

- Белая подложка для JPEG — как сейчас.
- Фон в результат попасть не может: рамка всегда внутри картинки.

### Сохранение поворота

```
rotate(delta):            // delta = +1 или −1
  quarterTurns = (quarterTurns + delta + 4) % 4
  обновить вид, рамку, hint
  if (tauri && currentPath):
    invoke("rotate_image", { path: currentPath, quarterTurns: delta })
      .catch(показать notice по тексту ошибки)
  else: один раз показать hint «открыт без пути»
```

- Каждый клик сразу отправляет команду, без задержки и без очереди в JS. Команда доработает в Rust, даже если окно закрыли и страница перезагрузилась ([main.rs](../../../src-tauri/src/main.rs), `hide_window`).
- Повороты складываются, поэтому порядок выполнения команд неважен.

### Ctrl+O через нативный диалог

- В десктопе `fileInput.click()` (Ctrl+O, кнопка 📂, клик по стартовому экрану) заменяется на `tauri.dialog.open({ filters: [{ name: "Изображения", extensions: ["jpg","jpeg","png"] }] })`. Выбранный путь открывается через `loadFromPath` и `initSiblings`, как файл из Проводника.
- Отмена диалога ничего не делает.
- В браузере остаётся `<input type=file>`.
- Права: `dialog:default` в `capabilities/default.json` уже разрешает `open`.

## Rust: команда `rotate_image`

```rust
#[tauri::command]
async fn rotate_image(path: String, quarter_turns: i32) -> Result<(), String>
```

- `quarter_turns` берётся по модулю 4 (+1 — вправо, −1 — влево). 0 означает ничего не делать.
- Тип файла определяет `mime_for`; не jpg/jpeg/png — ошибка `unsupported file type`.
- Атрибут «Только чтение» проверяется до любой записи и даёт ошибку `read-only`. Иначе в случае A запись на месте упала бы с невнятным `access denied`.
- Глобальный `static FILE_LOCK: Mutex<()>`: под ним выполняется каждый `rotate_image` и каждый `read_image`. Поэтому чтение (Prev/Next назад, повторное открытие, предзагрузка `Launch`) всегда видит уже повёрнутый файл.
- Команда регистрируется в `generate_handler!`. В CLAUDE.md число команд станет шесть.

### JPEG: тег Orientation

Модуль `src-tauri/src/exif.rs`, без новых зависимостей.

1. Пройти маркеры от SOI до SOS и найти APP1 с `Exif\0\0`. Разобрать TIFF-заголовок (`II` или `MM`) и IFD0. Любой выход смещений за границы — ошибка `corrupt EXIF`, файл не трогается.
2. Новое значение даёт таблица (покрывает все 8 значений, включая зеркальные):
   - вправо: `1→6→3→8→1` и `2→7→4→5→2`;
   - влево: обратные циклы.
   - Отсутствующий тег и значения вне 1…8 считаются 1, как в Chromium.
3. Три случая:

| Случай | Что делаем | Запись |
|---|---|---|
| **A.** Тег 0x0112 в IFD0 есть (SHORT, count 1) | меняем 2 байта значения | на месте: `OpenOptions::write`, `seek`, `write_all` по смещению |
| **B.** EXIF нет | после SOI и APP0/JFIF, если он есть, вставляем минимальный APP1: `Exif\0\0`, TIFF `II`, IFD0 из одной записи Orientation | файл целиком |
| **C.** EXIF есть, тега нет | копия IFD0 (включая указатель на IFD1) плюс запись 0x0112 (по порядку тегов) дописывается в конец TIFF-блока с выравниванием на чётный байт, смещение IFD0 в заголовке переставляется на неё. Остальные данные не двигаются, поэтому все смещения, включая maker notes, остаются верными. Если APP1 превысит 65535 байт — ошибка | файл целиком |

### PNG: поворот пикселей без потерь

Модуль `src-tauri/src/png_rotate.rs`, зависимость `png = "0.17"` (уже есть в Cargo.lock через Tauri).

1. Разобрать файл на чанки. Если есть `acTL` (анимированный PNG) — ошибка `animated PNG`.
2. Распаковать изображение крейтом `png` с `Transformations::IDENTITY`: сохраняются палитра, глубина 1/2/4/8/16 бит и альфа. Чересстрочные (interlaced) PNG распаковываются в обычные строки.
3. Повернуть пиксели. При глубине меньше 8 бит сначала распаковать биты, повернуть, упаковать обратно.
4. Сжать новые строки крейтом `png` с тем же цветовым типом и глубиной, без чересстрочности, с адаптивными фильтрами. Взять из результата только чанки `IDAT`.
5. Собрать файл:
   - новый `IHDR`: ширина и высота меняются местами, interlace = 0;
   - все остальные чанки оригинала по порядку и побайтно (PLTE, tRNS, iCCP, sRGB, gAMA, cHRM, tEXt, iTXt, zTXt, eXIf, неизвестные);
   - исключения: у `pHYs` оси меняются местами (CRC пересчитывается), старые `IDAT` заменяются новыми.
6. Запись — файл целиком.

### Запись файла целиком

- Байты пишутся во временный файл `.{имя}.pcc-tmp` в той же папке, затем им заменяется исходный.
  - Windows: `ReplaceFileW`. Сохраняет дату создания, атрибуты, права (ACL) и альтернативные потоки, включая Zone.Identifier. Нужна фича `Win32_Storage_FileSystem` у крейта `windows`.
  - Другие ОС: `fs::rename`.
- При любой ошибке временный файл удаляется, исходный не меняется.
- Дата изменения обновляется: по ней Проводник перерисовывает миниатюру.

### Ошибки

Команда возвращает строку, по которой страница выбирает текст сообщения:

| Код | Когда |
|---|---|
| `read-only` | атрибут «Только чтение» |
| `access denied` | нет прав |
| `corrupt EXIF` | битые метаданные |
| `animated PNG` | анимированный PNG |
| `unsupported file type` | не jpg/jpeg/png |
| прочее | текст ошибки ОС |

### Rust (`cargo test`)

**Таблица ориентации:**
- все 8 значений × вправо и влево совпадают с таблицей;
- 4 поворота вправо возвращают исходное значение;

**JPEG:**
- Случай A, II и MM: меняются ровно 2 байта, размер файла тот же.

- Значение тега 0 или 9 считается 1.

**PNG:**
- RGBA8, RGB16, Gray1, палитра с 4 битами + tRNS, Gray+Alpha: пиксель (x, y) оказался там, где должен, после поворота вправо и влево; размеры поменялись местами.
- 4 поворота дают те же пиксели, что в исходнике.
- Чанки iCCP, tEXt и неизвестный чанк сохранены побайтно; у pHYs оси поменялись местами.
- Чересстрочный PNG поворачивается и пишется без чересстрочности.
- Анимированный PNG (acTL): ошибка `animated PNG`, файл не тронут.

**Запись и команда:**
- Файл только для чтения: ошибка `read-only`, содержимое и атрибут не изменились, временного файла нет.
- Неподдерживаемое расширение отклоняется.
- 8 параллельных потоков по +1 дают Orientation исходного значения (8 ≡ 0 по модулю 4); файл не повреждён.
- `read_image`, запущенный во время поворота, получает уже повёрнутый файл (проверка блокировки).
- `quarter_turns` = 0, 4 и −4 ничего не делают; 5 работает как 1, −1 как 3.

### Геометрия (`tests/e2e/geometry.spec.mjs`, Node без браузера)

- `boundingSize` при 0°, 90° и 45° на квадрате.
- При 0° `clampBoxCenter` и `maxBoxSize` совпадают со старым зажатием по осям.
- На 10°, 30° и 45° после `clampBoxCenter` все углы рамки внутри картинки (`isBoxInside`) для 1000 случайных рамок с фиксированным seed.
- `maxBoxSize`: результат помещается, а рамка на 1 % больше уже нет.
- `maxWidthFromAnchor` для всех четырёх углов: внутри и максимальная (с точностью 0,5 px).

### Страница (`tests/e2e/rotate.spec.mjs`, моки Tauri)

Мок `installTauriMock` получает команду `rotate_image`:
- запросы пишутся в `__mockLog.rotations`;
- опция `rotateError` заставляет команду завершиться ошибкой;
- поворот файла хранится в `sessionStorage`, чтобы пережить перезагрузку страницы;
- `read_file_bytes` отдаёт заранее посчитанный в Node повёрнутый PNG.

## Риски

| Риск | Что делаем |
|---|---|
| Старые программы не читают EXIF-ориентацию | Принято сознательно. Физический поворот JPEG — в бэклог, если на практике встретится такая программа. |
| PNG после поворота становится больше оригинала (оригинал был сжат оптимизатором) | Без потерь, только размер. Тест проверяет пиксели, а не размер. |
| Большой PNG (8000×8000) поворачивается 1–2 с | Команда асинхронная, интерфейс не ждёт. Повороты, сделанные за это время, выполнятся по очереди под блокировкой. |
| Габарит stage меняется при наклоне, картинка на градус «дышит» (около 2 %) | Принято: так видна вся картинка с углами. |
