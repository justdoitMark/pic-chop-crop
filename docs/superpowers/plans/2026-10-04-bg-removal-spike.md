# Удаление фона AI — план пробного запуска (spike)

> **For agentic workers:** выполнять по этапам сверху вниз; у каждого этапа есть проверка «прошёл / не прошёл». Шаги — чекбоксы (`- [ ]`). Код пробного запуска — одноразовый, в приложение не встраивается.

**Цель:** за 1–2 вечера ответить на пять вопросов, после которых можно писать спек функции:

1. Какая модель даёт качество «карточка товара как есть» на наших реальных фото?
2. Насколько быстро она работает на RTX 5090 и на Intel Iris Xe (DirectML) и на процессоре (запасной путь)?
3. Работает ли выбранная модель через Rust `ort` + DirectML так же, как в Python (тот же результат, та же скорость)?
4. Сколько весит всё вместе (модель + DLL рантайма) → вшивать в установщик или качать при первом использовании?
5. Стоит ли перевести апскейлер 0.3.0 на тот же `ort` + DirectML вместо realesrgan-ncnn-vulkan?

**Не цель:** интерфейс, встраивание в `frontend/index.html`, AI-переосвещение (только по желанию — этап E).

**Приватность:** фото никуда не загружаются. Скрипты только читают локальные файлы; модели скачиваются один раз с Hugging Face. Папки с фото и моделями — в `.gitignore`.

## Что уже проверено (2026-10-04)

| Факт | Источник |
|---|---|
| `onnx-community/BiRefNet_lite-ONNX`: `model_fp16.onnx` 115 МБ, `model.onnx` 224 МБ | HF API, дерево `onnx/` |
| `onnx-community/BiRefNet-ONNX`: fp16 490 МБ, fp32 973 МБ | HF API |
| `onnx-community/BEN2-ONNX`: `model_fp16.onnx` 219 МБ; `PramaLLC/BEN2`: `BEN2_Base.onnx` 223 МБ | HF API |
| `onnx-community/ISNet-ONNX`: fp16 88 МБ, int8 44 МБ | HF API |
| BiRefNet, BEN2 — MIT; RMBG-2.0 — CC BY-NC (не берём) | карточки моделей |
| `onnxruntime-directml` 1.24.4 есть для Python 3.13 (`cp313-win_amd64`) | PyPI |
| `ort` (Rust) — последняя `2.0.0-rc.13`; готовые сборки **только для `x86_64-pc-windows-msvc`**, DirectML в них включён | crates.io, ort.pyke.io |
| На этом ноутбуке: Iris Xe, Rust `stable-x86_64-pc-windows-gnu`, MSVC нет, Python 3.13 | `rustup show`, `wmic` |

**Следствие для этапа D:** на GNU-тулчейне готовые сборки `ort` не подходят → используем фичу `load-dynamic` (DLL грузится в рантайме, линковки нет) и берём `onnxruntime.dll` + `DirectML.dll` из NuGet-пакетов. Это заодно и вероятный способ поставки в приложении.

**Не проверено (проверяется в спайке):** работа fp16 на Iris Xe через DirectML (в браузерных проектах fp16 иногда даёт мусорную маску), реальные размеры DLL, лицензия `pymatting`.

## Критерии решения (зафиксированы до замеров)

| Вопрос | Порог «да» |
|---|---|
| Качество | Выбранная модель: ≥ 7 из 10 фото оценены пользователем на 4–5 («беру в карточку как есть») |
| Скорость, RTX 5090 | Повторный прогон ≤ 0,5 с на 1024×1024 |
| Скорость, Iris Xe (DirectML) | Повторный прогон ≤ 2 с; первая загрузка модели ≤ 5 с |
| Запасной путь, процессор | ≤ 10 с на Iris Xe-ноутбуке (это аварийный режим, не основной) |
| Rust = Python | Маски отличаются больше чем на 8/255 не более чем у 1 % пикселей; время в пределах ±20 % |
| Размер | Модель + DLL ≤ ~150 МБ → вшиваем; больше → скачивание при первом использовании |

Если модель не проходит скорость на Iris Xe, но проходит на RTX — запоминаем как «на слабых ПК — лёгкая модель (ISNet/BiRefNet_lite), на сильных — полная».

## Этап A — подготовка и набор фото

- [ ] Создать ветку `spike/bg-removal` и папку `spikes/bg-removal/` с `.gitignore` (см. выше).
- [ ] Пользователь кладёт в `spikes/bg-removal/photos/` 10 своих фото (JPEG/PNG как с телефона, без уменьшения). Набор покрывает трудные случаи:
  1. рюкзак на диване (исходная идея);
  2. вещь с ремнями/шнурками/тонкими деталями;
  3. мех, ворс или волосы;
  4. прозрачное или стеклянное (бутылка, стакан);
  5. белый предмет на светлом фоне;
  6. тёмный предмет на тёмном фоне;
  7. блестящий/металлический предмет с бликами;
  8. предмет с надписью/этикеткой;
  9. два предмета рядом (что модель сочтёт «главным»);
  10. фото при плохом вечернем свете.
- [ ] `python -m venv .venv` → `pip install -r requirements.txt`.

**Проверка:** `python -c "import onnxruntime as o; print(o.get_available_providers())"` выводит список, где есть `DmlExecutionProvider`. Если нет — спайк на этой машине идёт только на CPU, записать в RESULTS.md.

## Этап B — модели и прогон в Python

Модели (fp16 и fp32 там, где есть оба):

| Ключ | Репозиторий | Роль |
|---|---|---|
| `isnet` | `onnx-community/ISNet-ONNX` | лёгкая база для сравнения |
| `birefnet_lite` | `onnx-community/BiRefNet_lite-ONNX` | главный кандидат по балансу |
| `birefnet` | `onnx-community/BiRefNet-ONNX` | потолок качества |
| `ben2` | `onnx-community/BEN2-ONNX` | конкурент по краям и волосам |

- [ ] `fetch_models.py`: через `huggingface_hub.hf_hub_download` скачать `onnx/model*.onnx` и `preprocessor_config.json` каждой модели в `models/<ключ>/`.
- [ ] Для каждой модели прочитать `preprocessor_config.json` (размер входа, `image_mean`, `image_std`, `do_rescale`) и `session.get_inputs()/get_outputs()` (имена, формы, тип fp16/fp32). **Не угадывать предобработку** — брать из этих файлов, записать в таблицу в RESULTS.md.
- [ ] `bench.py`: для каждой пары (модель, провайдер ∈ {`DmlExecutionProvider`, `CPUExecutionProvider`}) и каждого фото:
  - учесть EXIF Orientation при открытии (`ImageOps.exif_transpose`), как делает наше приложение;
  - ресайз до входа модели → нормализация → прогон → маска; если значения выхода вне [0, 1] — применить сигмоиду (проверить на первом фото и записать, нужна ли она);
  - маску растянуть до исходного размера (бикубически) → альфа-канал;
  - сохранить в `out/<модель>-<провайдер>/`: `mask.png`, `cut.png` (RGBA), `white.jpg`, `black.jpg`;
  - для DirectML с сессией: `session_ms` (создание сессии), `first_ms` (первый прогон), `warm_ms` (медиана 5 прогонов), `rss_mb` пик (`psutil`);
  - доля переднего плана (пиксели альфы > 0,5); если < 0,2 % или > 99,8 % — пометить `suspect` (признак сломанного fp16).
  - строка в `results.csv`: машина, GPU, модель, точность, провайдер, фото, тайминги, `rss_mb`, `fg_share`, `suspect`.
- [ ] Видеопамять: во время прогона снять `Get-Counter '\GPU Process Memory(*)\Dedicated Usage'` (PowerShell) для процесса Python, записать пик вручную в RESULTS.md.

**Проверка:** `results.csv` содержит строку на каждую комбинацию модель × провайдер × фото (до 4 × 2 × 2 точности × 10), в `out/` есть файлы для каждой строки; прогон без падений. Комбинации с `suspect` перечислены отдельно.

## Этап C — чистка краёв и оценка качества

Ореол цвета фона по контуру (диван «просвечивает» на волосках и краях) — главный дефект «дешёвого» удаления фона.

- [ ] Проверить лицензию `pymatting` (ожидаем MIT) — если не разрешительная, пропустить шаг и записать.
- [ ] Для лучших двух моделей сделать вариант с оценкой цвета переднего плана: `pymatting.estimate_foreground_ml(image, alpha)` → `white_clean.jpg`, `black_clean.jpg`. Записать время этого шага на 12 МП и 24 МП.
- [ ] `sheet.py` → `out/sheet.html`: строка на фото, столбцы — оригинал и для каждой модели «на белом / на чёрном / на шахматке» (+ «очищенный» вариант). Клик по ячейке — увеличение 1:1 на краю.
- [ ] Пользователь ставит каждой ячейке оценку 1–5 («5 — беру в карточку как есть»), Claude переносит оценки в RESULTS.md.

**Проверка:** таблица оценок 10 фото × модели заполнена; для каждой модели посчитано «сколько фото на 4–5». Сравнение с порогом ≥ 7/10.

## Этап D — тот же прогон через Rust `ort` + DirectML

Доказываем путь, которым функция пойдёт в приложение, на одной (лучшей по этапу C) модели.

- [ ] Скачать NuGet-пакеты `Microsoft.ML.OnnxRuntime.DirectML` и `Microsoft.AI.DirectML` (той же версии ORT, что требует `ort 2.0.0-rc.13`; версию взять из документации `ort`), достать `onnxruntime.dll` и `DirectML.dll` (x64) в `spikes/bg-removal/dll/`. Записать их размеры.
- [ ] `spikes/bg-removal/rs/` — отдельный крейт (не трогает `src-tauri/`): `ort = { version = "=2.0.0-rc.13", default-features = false, features = ["load-dynamic", "directml", "ndarray"] }`, `image`, `ndarray`.
  - путь к DLL задать через `ORT_DYLIB_PATH` (или программно при инициализации);
  - вход/нормализация — ровно как в Python (из таблицы этапа B);
  - CLI: `bg-remove-rs <model.onnx> <photo> <out_mask.png> [--cpu]`, печатает `session_ms first_ms warm_ms`.
- [ ] Собрать на этой машине GNU-тулчейном. `CARGO_TARGET_DIR` — вне пути с `&` (например `C:\pcc-target`), как в CLAUDE.md.
- [ ] Сравнить маску Rust с маской Python того же фото маленьким скриптом `compare.py` (доля пикселей с разницей > 8/255).

**Проверка:** сборка проходит; на 3 фото доля расходящихся пикселей ≤ 1 %; `warm_ms` в пределах ±20 % от Python на том же провайдере. Если `load-dynamic` на GNU не заводится — записать ошибку и повторить этот этап на RTX-ПК с MSVC (или в CI на `windows-latest`).

## Риски

| Риск | Что делаем |
|---|---|
| fp16 на Iris Xe даёт мусорную маску | флаг `suspect` в этапе B → берём fp32 для DirectML на Intel |
| BiRefNet полный не помещается/медленный на Iris Xe | ожидаемо; решение «лёгкая модель на слабых ПК» |
| `ort` + GNU + `load-dynamic` не собирается | этап D на MSVC (RTX-ПК или CI) |
| Модель выделяет не тот объект (фото №9) | записать; в функцию тогда нужен «клик по объекту» или ручная кисть — отдельная оценка сложности |
| Чистка краёв медленная на 24 МП | считать на уменьшенной копии и растягивать, или делать только в узкой полосе по краю маски |
